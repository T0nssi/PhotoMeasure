PhotoMeasure – คู่มือบำรุงรักษา / Maintenance Guide

คู่มือนี้ใช้ แก้ไขปัญหาและปรับปรุงโปรแกรมได้ด้วยตัวเอง โดยไม่ต้องใช้อินเทอร์เน็ต สำหรับผู้ที่เพิ่งเริ่มเขียนโปรแกรม หลักการสำคัญ 3 ข้อ: (1) ไม่แก้ตัวจริง แก้สำเนาเสมอ (2) แก้ทีละนิด แล้วทดสอบทันที (3) มีทางย้อนกลับเสมอ · เวอร์ชันโปรแกรม 0.6.0

สารบัญ
  1. เตรียมเครื่องมือ (ทำครั้งเดียวตอนมีอินเทอร์เน็ต)

  3. แผนที่โค้ด: ไฟล์ไหนทำอะไร
  4. วิธีหาจุดที่ต้องแก้
  5. ขั้นตอนแก้ไขอย่างปลอดภัย
  6. สูตรแก้ไขที่ใช้บ่อย (ทำตามได้ทีละขั้น)
  7. เมื่อโปรแกรมมีปัญหา: วิธีหาสาเหตุ
  8. ทดสอบตัวเอง (Self-Test)
  9. นำเวอร์ชันใหม่ไปใช้งานจริง และการย้อนกลับ
  10. สร้าง Camera Bridge ใหม่ (เมื่อแก้ไฟล์ .cs)
  11. คำศัพท์

1. เตรียมเครื่องมือ (ทำครั้งเดียวตอนมีอินเทอร์เน็ต)

ดาวน์โหลดตัวติดตั้งแบบ offline เก็บไว้ใน USB หลังติดตั้งแล้วใช้งานได้โดยไม่ต้องมีอินเทอร์เน็ต

เครื่องมือใช้ทำอะไรจำเป็น?
Google Chrome หรือ Microsoft Edgeเปิดโปรแกรม และดูข้อผิดพลาด (F12)จำเป็น
Visual Studio Code (ตัวติดตั้ง “System Installer x64”)เปิดและแก้ไขโค้ด ค้นหาข้อความในทุกไฟล์ (Ctrl+Shift+F) มีเลขบรรทัด และขีดเส้นใต้จุดที่พิมพ์ผิดแนะนำ (ใช้ Notepad ได้ แต่ยากกว่า)
Git for Windows (หรือ GitHub Desktop)เก็บประวัติทุกการแก้ไข ดูว่าแก้อะไรไป และย้อนกลับได้แนะนำมาก
.NET 8 SDK x64 (หรือใหม่กว่า)สร้าง Camera Bridge ใหม่ เมื่อแก้ไฟล์ .csเฉพาะเมื่อแก้ส่วนกล้อง
Basler pylon (Developer) + ASP.NET Core Runtimeใช้กล้อง (มีอยู่แล้วที่เครื่องสถานี)เฉพาะเครื่องที่ต่อกล้อง

2. โปรแกรมทำงานอย่างไร

โปรแกรมมี 2 ส่วน:

  • แอปในเบราว์เซอร์ (โฟลเดอร์ app) – หน้าจอทั้งหมด การวัด รายงาน เขียนด้วย HTML + CSS + JavaScript แก้ไฟล์แล้วกด F5 ในเบราว์เซอร์ก็เห็นผลทันที ไม่ต้องคอมไพล์
  • Camera Bridge (โฟลเดอร์ CameraBridge) – โปรแกรมเล็กใน Windows ที่คุยกับกล้องผ่าน pylon เขียนด้วย C# ถ้าแก้ไฟล์ .cs ต้องสร้างใหม่ (หัวข้อ 10)

เส้นทางของการวัด 1 ภาพ

ภาพ (ไฟล์ / กล้อง)→vision.js
โหลดภาพ หาวงกลม→engine.js
หา REF → วัดขอบ → คำนวณขนาด → OK/NG→app.js
แสดงผล→report.js
Excel/PDF/Word

เส้นทางของภาพจากกล้อง

ปุ่ม 📷 ถ่ายภาพ
camera.js→Camera Bridge
/api/grab→CameraService.cs→PylonDriver.cs → pylon → กล้อง→ภาพกลับมาที่ app.js แล้ววัดเหมือนภาพถ่าย

ข้อมูลเก็บที่ไหน: ผู้ใช้และโปรแกรมการวัดเก็บใน เบราว์เซอร์ (สำรองด้วยปุ่ม ⬇ Backup ที่แท็บผู้ใช้งาน) · ภาพจากกล้อง ภาพที่บันทึก และ log เก็บที่ CameraBridge\data · ค่าตั้งของ Bridge อยู่ที่ CameraBridge\bridge.config.json

3. แผนที่โค้ด: ไฟล์ไหนทำอะไร

ระดับความเสี่ยง: ต่ำ แก้ได้สบายใจ · กลาง ทดสอบให้ดี · สูง กระทบความถูกต้องของการวัด ต้องผ่าน Self-Test และเทียบกับเครื่องมือวัดจริง

ไฟล์หน้าที่ความเสี่ยง
app/index.htmlหน้าจอ ปุ่ม ช่องกรอก (โครงสร้างหน้าจอ)ต่ำ
app/css/style.cssสี ขนาดตัวอักษร การจัดวางต่ำ
app/js/i18n.jsข้อความภาษาอังกฤษ/ไทย ทั้งหน้าจอและรายงานต่ำ
app/js/help.js + app/help/คู่มือการทำงานในแท็บวิธีใช้ และรูปภาพต่ำ
app/js/report.jsรายงาน Excel, PDF, Word, CSVกลาง
app/js/app.jsการทำงานของปุ่มในแท็บโปรแกรมการวัด วัดภาพถ่าย รายงาน ผู้ใช้งานกลาง
app/js/camera.jsแท็บกล้อง: เชื่อมต่อ ภาพสด ถ่ายภาพ บันทึกภาพกลาง
app/js/timing.jsเวลาประมวลผล: สถิติ เวลาไซเคิลสูงสุด CSVต่ำ
app/js/calibui.jsการ์ดสอบเทียบสถานีในแท็บกล้อง (ปุ่ม ภาพผล ประวัติ)กลาง
app/js/charml.jsตัวอ่านตัวอักษรที่สอนเอง: ตัดตัวอักษร ทำภาพ 32×32 เก็บข้อมูล (IndexedDB) สอนโมเดล (Web Worker) อ่านสูง
app/js/trainui.jsแท็บ Training: ภาพตัวอักษร ป้ายชื่อ สอน รายการตัวอ่าน นำเข้า/ส่งออกกลาง
app/js/calib.jsคำนวณสเกลจากแผ่นสอบเทียบ (dot grid) และเก็บค่าการสอบเทียบสูง
app/js/auth.js, library.jsผู้ใช้/รหัสผ่าน และคลังโปรแกรมกลาง
app/js/engine.jsหัวใจของการวัด: REF มาตราส่วน การหมุน ขนาด ข้อกำหนด OK/NGสูง
app/js/vision.js, geom.js, ocr.jsประมวลผลภาพ หาขอบ หาวงกลม คำนวณเรขาคณิต อ่านตัวอักษรสูง
app/lib/ไลบรารีภายนอก (OpenCV, Excel, PDF …)ห้ามแก้
CameraBridge/bridge.config.jsonค่าตั้ง Bridge: พอร์ต โฟลเดอร์ ชื่อไฟล์ จำนวนวันเก็บ (ไม่ต้องสร้างใหม่)ต่ำ
CameraBridge/source/CameraBridge/*.csโค้ด Camera Bridge (ต้องสร้างใหม่หลังแก้)กลาง
…/Drivers/PylonDriver.csการคุยกับกล้องผ่าน pylonสูง

4. วิธีหาจุดที่ต้องแก้

วิธีหลัก: ข้อความบนหน้าจอ → id → โค้ด

  1. เปิดโฟลเดอร์ PhotoMeasure ใน VS Code (File → Open Folder)
  2. กด Ctrl+Shift+F พิมพ์ข้อความที่เห็นบนหน้าจอ เช่น Save image
  3. จะพบใน index.html หรือ i18n.js เช่น <button … id="cSaveNow" …> หรือ camSaveNow: ["💾 Save image", "💾 บันทึกภาพ"]
  4. ค้นหา id นั้นอีกครั้ง เช่น cSaveNow → พบใน camera.js ที่บรรทัด $("#cSaveNow").addEventListener("click", …) นี่คือโค้ดที่ทำงานเมื่อกดปุ่ม

อีกวิธี: ใช้เบราว์เซอร์ คลิกขวาที่ปุ่ม → Inspect (ตรวจสอบ) จะเห็น id ของปุ่มนั้น

อ่านโค้ด JavaScript เบื้องต้น

const S = { … }                 // const/let = ตัวแปร (ที่เก็บค่า)
function grab(opt) { … }       // function = ชุดคำสั่งที่มีชื่อ เรียกใช้ได้
$("#cGrab")                    // หา element ในหน้าจอที่มี id="cGrab"
.addEventListener("click", …)  // เมื่อคลิก ให้ทำ …
if (it.status === "OK") { … }  // ถ้า … ให้ทำ …
// ข้อความหลัง // คือคำอธิบาย ไม่มีผลต่อโปรแกรม

ทุกไฟล์มีคำอธิบายหน้าที่อยู่ที่บรรทัดแรก ๆ และชื่อฟังก์ชันบอกหน้าที่ เช่น processItem = วัดภาพ 1 ภาพ, renderReportTab = วาดแท็บรายงาน

5. ขั้นตอนแก้ไขอย่างปลอดภัย

  1. สำเนาก่อน: คัดลอกโฟลเดอร์ทั้งหมดเป็น PhotoMeasure_test แก้เฉพาะในสำเนา ห้ามแก้เครื่องที่ใช้งานจริงโดยตรง
  2. บันทึกจุดเริ่มต้นด้วย Git (ทำครั้งแรกครั้งเดียว) เปิด Command Prompt ในโฟลเดอร์สำเนา: 
    git init
git add -A
git commit -m "v0.6.0 original"
    ถ้าไม่มี Git: ทำ zip สำเนาไว้ ตั้งชื่อตามวันที่
  3. รัน Self-Test ก่อนแก้ (หัวข้อ 8) ต้องผ่านทั้งหมด
  4. แก้ทีละเรื่องเล็ก ๆ บันทึกไฟล์ (Ctrl+S) แล้วกด F5 ในเบราว์เซอร์
  5. ดู Console (F12) ว่ามีข้อความสีแดงหรือไม่ (หัวข้อ 7)
  6. รัน Self-Test อีกครั้ง และลองใช้งานส่วนที่แก้
  7. ดูสิ่งที่เปลี่ยน และบันทึก: 
    git diff                          (ดูบรรทัดที่เปลี่ยน: - ของเดิม, + ของใหม่)
git add -A
git commit -m "เปลี่ยนค่าพิกัดเริ่มต้นเป็น 0.05"
  8. ถ้าพัง ย้อนกลับ: 
    git checkout -- app/js/engine.js  (ยกเลิกการแก้ไฟล์นี้ที่ยังไม่ได้ commit)
git log --oneline                 (ดูประวัติ)
git revert <รหัส>                  (ยกเลิก commit ที่ทำให้พัง)
กฎทอง: ถ้าไม่แน่ใจ อย่าลบโค้ด ให้ “ปิด” โดยใส่ // หน้าบรรทัด และเขียนอธิบายว่าทำไม · เปลี่ยนตัวเลขทีละค่า · อย่าแก้ไฟล์ใน lib/

6. สูตรแก้ไขที่ใช้บ่อย

ใช้ Ctrl+Shift+F ค้นหา “ข้อความค้นหา” ตามตาราง (เลขบรรทัดอาจเปลี่ยนตามเวอร์ชัน จึงค้นหาด้วยข้อความ)

6.1 เปลี่ยนข้อความบนหน้าจอหรือในรายงาน (ไทย/อังกฤษ) ต่ำ

ไฟล์ app/js/i18n.js แต่ละบรรทัดคือ คีย์: ["อังกฤษ", "ไทย"] เช่น

report: ["Measurement report", "รายงานผลการวัด"],

แก้เฉพาะข้อความในเครื่องหมาย " " ห้ามลบเครื่องหมาย , [ ] " · ข้อความที่ไม่มีใน i18n.js แก้ใน index.html

6.2 เปลี่ยนสี OK / NG / CHECK ต่ำ

app/css/style.css บรรทัดบน ๆ: --ok: #2fb36b; --bad: #e5534b; --warn: #e3a52b; (โหมดมืด) และบล็อก [data-theme="light"] (โหมดสว่าง)

6.3 ค่าพิกัดความเผื่อเริ่มต้น ±0.1 กลาง

app/js/app.js ค้นหา d.tolP = d.tolM = 0.1 เปลี่ยน 0.1 เป็นค่าที่ต้องการ (มีผลกับรายการวัดที่สร้างใหม่เท่านั้น)

6.4 ความละเอียดขั้นต่ำ 20 px/mm (คำเตือน low resolution) กลาง

ปรับได้ในโปรแกรม (ช่อง Min px/mm) ไม่ต้องแก้โค้ด ค่าเริ่มต้นอยู่ที่ engine.js ค้นหา minPxPerMm: 20

6.5 ค่าเริ่มต้นการหาขอบของเครื่องมือใหม่ สูง

engine.js ค้นหา const defaultEdge (thr: 12 = ความต่างความสว่างขั้นต่ำ) มีผลเฉพาะเครื่องมือที่สร้างใหม่ ปรับรายเครื่องมือได้ในโปรแกรมอยู่แล้ว

6.6 รหัสผ่านขั้นต่ำ 4 ตัวอักษร กลาง

app/js/auth.js ค้นหา length < 4 (มี 2 จุด) และข้อความ at least 4 characters

6.7 ขนาดภาพที่ใช้วัด สูง

app.js บรรทัดที่ 8: MASTER_MAX = 2600 (ภาพต้นแบบ), CAM_MAX = 6000 (ภาพจากกล้อง) และค้นหา 4096 (ภาพถ่ายทั่วไป) ค่ามาก = ละเอียดขึ้นแต่ช้าและใช้หน่วยความจำมากขึ้น

6.8 ภาพสด: จำนวนภาพต่อวินาที / ความละเอียด ต่ำ

camera.js ค้นหา fps: 10 และ Math.min(1600 (ขนาดภาพสดสูงสุด)

6.9 ปุ่มลัดถ่ายภาพ (Space) ต่ำ

camera.js ค้นหา e.code !== "Space" เปลี่ยนเป็นปุ่มอื่น เช่น "F2" หรือ "Enter" (foot switch ส่วนใหญ่ตั้งให้ส่งปุ่มใดก็ได้)

6.10 ค่าตั้ง Camera Bridge (ไม่ต้องแก้โค้ด) ต่ำ

ปิด Bridge แล้วแก้ CameraBridge\bridge.config.json ด้วย Notepad: port, keepShotDays, record.pattern (ชื่อไฟล์), record.folder, defaultCamera · บันทึก แล้วเปิด Bridge ใหม่ (ถ้าพิมพ์ผิด Bridge จะใช้ค่าเริ่มต้นและแจ้งในหน้าต่างดำ)

6.11 เพิ่มค่าตั้งกล้องในแผงตั้งค่า กลาง

CameraBridge/source/CameraBridge/Drivers/Camera.cs รายการ Features.All เพิ่มบรรทัด เช่น
FeatureDef.F("SensorReadoutTime", "Timing", "Sensor readout (µs)"),
ชื่อแรกต้องตรงกับชื่อใน pylon Viewer (Feature name) แล้วสร้าง Bridge ใหม่ (หัวข้อ 10)

6.12 เพิ่ม/เปลี่ยนคอลัมน์รายงาน กลาง

report.js: Excel อยู่ในฟังก์ชัน xlsx(ctx), PDF ใน pdf(ctx), Word ใน docxReport(ctx), CSV ใน csv(ctx) ข้อความหัวข้อมาจาก i18n.js

6.13 เกณฑ์ตรวจการสอบเทียบประจำวัน ±0.05 % กลาง

calib.js ค้นหา limitPct = 0.05 · อายุการสอบเทียบตั้งได้ในหน้าจอ (ช่อง ใช้ได้ (วัน)) ไม่ต้องแก้โค้ด

6.14 เกณฑ์ “ชิ้นงานใหญ่/เล็กกว่าต้นแบบ” ในโหมด Fixed calibration สูง

engine.js ค้นหา sc.from === "spacing" ? 1 : 4 (1 % เมื่อเทียบระยะระหว่างวงกลม, 4 % เมื่อเทียบเส้นผ่านศูนย์กลาง) ห้ามตั้งกว้างเกินไป เพราะเป็นตัวป้องกันผลผิดเมื่อความสูงชิ้นงานหรือระยะกล้องเปลี่ยน

6.15 เพิ่มขั้นตอนในตารางเวลาประมวลผล ต่ำ

ใน processItem ของ app.js เรียก lap("ชื่อขั้นตอน") หลังขั้นตอนนั้น (หรือใน measure ของ engine.js) แล้วเพิ่มชื่อเดียวกันในรายการ STEPS ของ timing.js

4. Finding the code to change

Main method: screen text → id → code

  1. Open the PhotoMeasure folder in VS Code (File → Open Folder).
  2. Press Ctrl+Shift+F and type the text you see, e.g. Save image.
  3. You find it in index.html or i18n.js, e.g. <button … id="cSaveNow" …> or camSaveNow: ["💾 Save image", "💾 บันทึกภาพ"].
  4. Search that id, cSaveNow → in camera.js: $("#cSaveNow").addEventListener("click", …). This is the code that runs on the click.

Or in the browser: right-click the button → Inspect shows its id.

Reading JavaScript, the basics

const S = { … }                 // const/let = a variable (holds a value)
function grab(opt) { … }       // function = named list of instructions
$("#cGrab")                    // the element on the screen with id="cGrab"
.addEventListener("click", …)  // when it is clicked, do …
if (it.status === "OK") { … }  // if … then …
// text after // is a comment and does nothing

Every file starts with a comment saying what it does, and function names say what they do: processItem = measure one photo, renderReportTab = draw the report tab.

5. Safe change workflow

  1. Copy first: copy the whole folder to PhotoMeasure_test and change only the copy. Never edit the station PC directly.
  2. Mark the starting point with Git (once). Command Prompt in the copy: 
    git init
git add -A
git commit -m "v0.6.0 original"
    Without Git: zip the copy and name it with the date.
  3. Run the Self-Test before the change (section 8): all must pass.
  4. One small change at a time. Save (Ctrl+S) and press F5 in the browser.
  5. Look at the Console (F12) for red messages (section 7).
  6. Run the Self-Test again and try the part you changed.
  7. Review and save: 
    git diff                          (changed lines: - old, + new)
git add -A
git commit -m "default tolerance 0.05"
  8. If it breaks, go back: 
    git checkout -- app/js/engine.js  (undo changes of this file not yet committed)
git log --oneline                 (history)
git revert <id>                    (undo the commit that broke it)
Golden rules: when unsure, don't delete code: switch it off with // in front and write why · change one number at a time · never edit files in lib/.

6. Common changes

Use Ctrl+Shift+F with the search text given (line numbers change between versions, so search by text).

6.1 Change a text on the screen or in reports (EN/TH) low

app/js/i18n.js, each line is key: ["English", "Thai"], e.g.

report: ["Measurement report", "รายงานผลการวัด"],

Change only the text inside " ". Do not delete , [ ] ". Texts not in i18n.js are in index.html.

6.2 Colours of OK / NG / CHECK low

app/css/style.css top lines: --ok: #2fb36b; --bad: #e5534b; --warn: #e3a52b; (dark mode) and the [data-theme="light"] block (light mode).

6.3 Default tolerance ±0.1 medium

app/js/app.js, search d.tolP = d.tolM = 0.1, change 0.1 (only for new dimensions).

6.4 Minimum resolution 20 px/mm (low-resolution warning) medium

Set in the program (Min px/mm field); no code. The default is in engine.js, search minPxPerMm: 20.

6.5 Edge defaults for new tools high

engine.js, search const defaultEdge (thr: 12 = minimum brightness step). New tools only; each tool can already be adjusted in the program.

6.6 Minimum password length 4 medium

app/js/auth.js, search length < 4 (2 places) and the text at least 4 characters.

6.7 Image size used for measuring high

app.js line 8: MASTER_MAX = 2600 (master), CAM_MAX = 6000 (camera), and search 4096 (photos). Bigger = finer but slower and more memory.

6.8 Live view frame rate / resolution low

camera.js, search fps: 10 and Math.min(1600 (largest live image).

6.9 Grab shortcut key (Space) low

camera.js, search e.code !== "Space", change to e.g. "F2" or "Enter" (most foot switches can send any key).

6.10 Camera Bridge settings (no code) low

Close the bridge, edit CameraBridge\bridge.config.json with Notepad: port, keepShotDays, record.pattern (file name), record.folder, defaultCamera. Save and start the bridge (a typo makes it use defaults and say so in the black window).

6.11 Add a camera setting to the setup panel medium

CameraBridge/source/CameraBridge/Drivers/Camera.cs, list Features.All, add a line, e.g.
FeatureDef.F("SensorReadoutTime", "Timing", "Sensor readout (µs)"),
The first name must be the feature name shown in pylon Viewer. Then rebuild (section 10).

6.12 Report columns medium

report.js: Excel in xlsx(ctx), PDF in pdf(ctx), Word in docxReport(ctx), CSV in csv(ctx). Header texts come from i18n.js.

6.13 Daily calibration check limit ±0.05 % medium

calib.js, search limitPct = 0.05. The validity (days) is set on the screen (Valid for field), no code.

6.14 “Part larger / smaller than the master” limit in Fixed-calibration mode high

engine.js, search sc.from === "spacing" ? 1 : 4 (1 % for the spacing of circles, 4 % for a diameter). Do not open it up too far: it protects against wrong results when the part height or the camera distance changes.

6.15 Add a step to the processing-time table low

In processItem of app.js call lap("stepname") after the step (or in measure of engine.js), then add the same name to the STEPS list in timing.js.

8. Self-Test

Open app/selftest.html (double-click, or http://127.0.0.1:5090/selftest.html when the bridge runs) and press ▶ Run all tests (about 10 s, no internet).

  • Measures 3 sample photos with a fixed program and compares every value with the reference (distances/diameters within 0.01 mm, ΔE 0.5, texts exactly, OK/NG exactly).
  • Station calibration: a synthetic dot-grid plate (scale error ≤ 0.02 %) · a part image turned 12° and shifted must give the same angle and values · the blocks for wrong images.
  • Builds Excel, PDF, Word and CSV reports.
  • Checks the Camera Bridge, pylon and the camera (tick “Grab one camera image” to test a real grab).
Example: an error of only 0.5 % in the diameter calculation (0.015 mm) makes the Self-Test FAIL.

When you change measuring results on purpose (e.g. better edge detection): first check the new values with a real gauge (CMM/OMM/micrometer), then press ⬇ New reference… and replace app/selftest/selftest-data.js with the downloaded file.

9. Releasing a new version and rolling back

Before release

✓Check
☐Self-Test all PASS (save the .txt result)
☐log in as Admin and as Operator
☐open one real program, measure known OK and NG parts: same results as before
☐camera: live view, grab, save image (if a camera is used)
☐export one report and open it
☐new version number in the folder name, e.g. PhotoMeasure_v0.5.4, and a note of what changed

On the day

  1. On the station PC: ⬇ Backup (users + programs) in the Users tab; keep the file.
  2. Close the Camera Bridge. Do not delete the old folder: rename it PhotoMeasure_v0.6.0_old.
  3. Copy the new folder to the old place. Copy CameraBridge\bridge.config.json and CameraBridge\data from the old folder.
  4. Start it and run the Self-Test on that PC.
  5. Run it next to the old method for a shift to a week and compare some parts. Do it in a quiet period.

Roll back (2 minutes)

Close the bridge → rename the new folder away → rename …_old back → start the bridge. (Users and programs stay in the browser; if they are missing, restore the backup.)

10. Rebuilding the Camera Bridge (after editing .cs files)

  1. Install the .NET 8 SDK x64 once. Building works offline: the bridge uses no internet packages.
  2. Close the Camera Bridge.
  3. Double-click CameraBridge\Build-Bridge.cmd. Build succeeded = done; CameraBridge.dll is replaced.
  4. An error names the file and line, e.g. Camera.cs(52,9): error CS1002: ; expected = line 52 misses a ;.
  5. Test with the simulated camera: Start-Simulator.cmd, then the Self-Test.

Testing the pylon part without a camera: source\FakePylon is a stand-in of the pylon API for developers (see CameraBridge\README.md).
